## Native build evidence and next step

The final offline command was `mobileapp/android/gradlew.bat :app:assembleDebug --offline --no-daemon --console=plain`. Gradle successfully resolved the relocated project, Expo/native module configuration, native autolinking and codegen. Dependency metadata processing could not download uncached artifacts including AndroidX core-splashscreen 1.2.0-alpha02, Firebase messaging 24.1.1/installations, Fresco 3.6.0, Hermes Android 0.79.6 debug and other AndroidX AARs. An online build was attempted first, but thread inspection showed blocking SSL reads and it made no progress after configuration. Only that task's identified daemon/children were stopped. Retry without `--offline` on a host with working Maven/Google artifact access; native compilation and device behavior remain unverified.

Earlier dependency-repair attempts failed on a missing Babel package, a missing Router `query-string` dependency and Metro relative `.js`/source `.ts` resolution. They were corrected with a clean npm install, explicit compatible Router dependency, and common compiled shared exports. Successful exports/browser checks followed. An early native attempt overlapped dependency replacement; the later isolated offline attempt provides the meaningful native-path result.

## Dependency security

The root workspace audit reached **zero known vulnerabilities** after compatible fixes and explicit patched Nodemailer/Firebase Admin versions. Mobile remains on Expo SDK 53 to preserve its native compatibility: the final audit reports **41 findings: 4 high, 36 moderate, 1 low, 0 critical**. High findings concern `brace-expansion`, `decode-uri-component`, `image-size`, and the dependent `query-string` navigation helper. gRPC and PostCSS were patched with compatible overrides. Older toolchain fixes offered by audit include breaking Expo/React Native upgrades; blanket overrides would change APIs (for example old callable CommonJS exports versus newer module objects), so they were not applied blindly. A separate tested SDK/library upgrade is required before production acceptance.

## Explicitly limited or blocked functionality

- Eight validated market pairs remain shared with the modern web app. Quotes/trades for the other legacy mobile pairs are blocked outside that registry, including retired symbols. See mobile README for the exact list. Existing unsupported ledgers are preserved and return a review error; no silent rounding, reassignment or data deletion occurs.
- Guest browser portfolios retain their old local format/keys and remain independent of authenticated mobile records. No automatic cross-device/guest-account merge is implied.
- Numeric model-specific predictions, ungrounded generated headlines, static fabricated exchange statistics, forced refresh and arbitrary-user push tests are retired. Both apps show explicit unavailable prediction/news states.
- Existing accounts need a configured reachable MongoDB; new verification needs SMTP; delivered alerts need Firebase credentials plus both server/client opt-ins. One token per account matches the historical schema. Pending verification and rate limits assume a single API process. Alerts are best effort, not exactly-once delivery.
- Native release artifacts are intentionally unsigned until the owner configures release credentials; the old debug signing assignment was removed. Android permissions/backup were updated directly in the retained native project. Other app-config/native changes require explicit synchronization.
- The modern web UI and design were retained. Mobile core services/adapters are typed; many platform UI components remain JavaScript, checked by lint/bundle/browser regression rather than claiming a full TS conversion.

Historical embedded credentials still require owner revocation/rotation; source cleanup does not erase history. See SECURITY.md and REVIEW_GUIDE.md before committing or deploying.
