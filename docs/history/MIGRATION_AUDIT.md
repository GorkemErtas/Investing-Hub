## Controlled implementation sequence

1. Record audit and complete legacy endpoint matrix before source changes.
2. Establish universal `shared` package (contracts, Decimal ledger, technical analysis), move modern backend into root, add optional Mongo/auth/settings/notification modules with explicit dependencies.
3. Preserve schema/collection compatibility, validate full transaction replay and serialize concurrent writes safely. Test with an injected repository and, when available, real Mongo.
4. Redirect web imports/scripts to shared/backend; preserve guest behavior and browser storage. Move Python pipeline to root `ml`; archive duplicate model artifacts once with checksums.
5. Refactor mobile API/auth/portfolio/market adapters in place; preserve navigation, Learning Hub, themes, favorites and CRUD. Explicitly block inaccurate or unsafe legacy features.
6. Only after shared/backend exist, move mobile-only app/native/assets/config/manifests into `mobileapp`. Update Metro, native entry, EAS, environment, scripts and dependency paths.
7. Run available shared/backend/web/mobile/Python checks and actual browser regressions. Record environment failures precisely; do not equate bundle success with native build or unit tests with live service integration.
8. Finish architecture/setup/deployment/verification reports and exact proposed staging groups. All modifications remain unstaged and uncommitted.

Dependency decision: Expo SDK 53 supports monorepos but expects React 19.0 and recommends hoisted dependencies. Keep its install separate from the web's React 19.2 workspace; publish no package and use a local shared package with universal exports. References: [Expo monorepos](https://docs.expo.dev/guides/monorepos/), [SDK 53](https://expo.dev/changelog/sdk-53), [SecureStore](https://docs.expo.dev/versions/v53.0.0/sdk/securestore/).
